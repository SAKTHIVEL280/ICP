# Internal Complaint Portal - Database Design

## Overview

The Internal Complaint Portal uses **PostgreSQL** as its relational
database. The database is normalized (3NF) to minimize redundancy while
ensuring efficient querying and maintainability. SQLAlchemy ORM maps the
application models to the database tables.

------------------------------------------------------------------------

# Database Architecture

``` text
Application (Flask)
        │
        ▼
 SQLAlchemy ORM
        │
        ▼
 PostgreSQL Database
```

------------------------------------------------------------------------

# Database Design Principles

-   Third Normal Form (3NF)
-   Primary and Foreign Keys
-   ENUM types for fixed values
-   Audit logging for system activities
-   Referential integrity using foreign keys
-   Automatic timestamps

# Database Tables

## 1. departments

  Column        Type           Constraints
  ------------- -------------- ------------------
  id            SERIAL         Primary Key
  name          VARCHAR(100)   Unique, Not Null
  description   TEXT           Nullable

------------------------------------------------------------------------

## 2. categories

  Column          Type           Constraints
  --------------- -------------- ---------------------
  id              SERIAL         Primary Key
  name            VARCHAR(100)   Not Null
  department_id   INTEGER        FK → departments.id

Relationship: - One Department → Many Categories

------------------------------------------------------------------------

## 3. users

  Column          Type
  --------------- --------------
  id              SERIAL
  employee_id     VARCHAR(20)
  name            VARCHAR(100)
  email           VARCHAR(120)
  password        TEXT
  role            ENUM
  department_id   INTEGER
  is_active       BOOLEAN
  created_at      TIMESTAMP

Constraints - Primary Key: id - Unique: employee_id - Unique: email -
FK: department_id → departments.id

------------------------------------------------------------------------

## 4. complaints

  Column             Type
  ------------------ --------------
  id                 SERIAL
  complaint_number   VARCHAR(20)
  title              VARCHAR(200)
  description        TEXT
  category_id        INTEGER
  department_id      INTEGER
  employee_id        INTEGER
  technician_id      INTEGER
  priority           ENUM
  status             ENUM
  location           VARCHAR(150)
  resolution_note    TEXT
  created_at         TIMESTAMP
  updated_at         TIMESTAMP
  closed_at          TIMESTAMP

Relationships - Category → Complaint - Department → Complaint - Employee
→ Complaint - Technician → Complaint

------------------------------------------------------------------------

## 5. comments

  Column         Type
  -------------- -----------
  id             SERIAL
  complaint_id   INTEGER
  user_id        INTEGER
  comment        TEXT
  created_at     TIMESTAMP

Relationships - Complaint → Many Comments - User → Many Comments

------------------------------------------------------------------------

## 6. attachments

  Column         Type
  -------------- --------------
  id             SERIAL
  complaint_id   INTEGER
  filename       VARCHAR(255)
  filepath       TEXT
  uploaded_by    INTEGER
  uploaded_at    TIMESTAMP

------------------------------------------------------------------------

## 7. complaint_history

  Column         Type
  -------------- -----------
  id             SERIAL
  complaint_id   INTEGER
  old_status     ENUM
  new_status     ENUM
  updated_by     INTEGER
  updated_at     TIMESTAMP

Purpose - Stores every status transition of a complaint.

------------------------------------------------------------------------

## 8. notifications

  Column       Type
  ------------ -----------
  id           SERIAL
  user_id      INTEGER
  message      TEXT
  is_read      BOOLEAN
  created_at   TIMESTAMP

Purpose - Stores user notifications generated by system events.

------------------------------------------------------------------------

## 9. activity_logs

  Column        Type
  ------------- --------------
  id            SERIAL
  user_id       INTEGER
  action        VARCHAR(150)
  entity_type   VARCHAR(50)
  entity_id     INTEGER
  old_value     JSONB
  new_value     JSONB
  created_at    TIMESTAMP

Purpose - Maintains a complete audit trail.

# Relationships

-   Department (1) → (M) Categories

-   User (Employee) (1) → (M) Complaints
-   User (Technician) (1) → (M) Complaints
-   Complaint (1) → (M) Comments

-   complaints(status)
-   complaints(priority)
-   complaints(created_at)
-   complaints(department_id)
-   complaints(technician_id)
-   comments(complaint_id)
-   notifications(user_id)

------------------------------------------------------------------------

# Data Integrity

-   NOT NULL constraints on mandatory fields
-   UNIQUE constraints for email and employee ID
-   FOREIGN KEY constraints
-   CHECK constraints for valid values where appropriate
-   ON DELETE RESTRICT for referenced master data
-   ON DELETE CASCADE for child records like comments and attachments

# Summary

The database design follows relational database best practices using
PostgreSQL. It is normalized, enforces referential integrity through
foreign keys, uses ENUM types for fixed-value fields, supports audit
logging, and provides a scalable foundation for complaint tracking,
assignment, notifications, reporting, and future enhancements.
